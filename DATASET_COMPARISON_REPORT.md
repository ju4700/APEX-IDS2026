## 1. Executive Summary

APEX-IDS2026 and CIC-IDS2017 are both network intrusion detection datasets but represent fundamentally different philosophies of data collection. CIC-IDS2017 is a **controlled laboratory simulation** generated by researchers running known attack tools against machines they owned. APEX-IDS2026 is a **real-world honeypot capture** of actual global attackers attempting to compromise a live internet-exposed system over 44 days.

The two datasets are not interchangeable — they answer different research questions. However, across every measurable dimension of dataset quality, APEX-IDS2026 is objectively superior.

## 3. Collection Methodology

### CIC-IDS2017
- Collected at the **Canadian Institute for Cybersecurity (UNB)** in 2017
- Entirely **simulated**: researchers manually ran attack tools (LOIC, GoldenEye, Slowloris, etc.) against an internal lab network
- **No real attacker involvement** — every attack was scripted and expected
- Network was completely isolated from the internet
- All traffic was captured from a controlled environment with known ground truth
- Features were extracted using **CICFlowMeter** — a purpose-built Java tool
- Raw PCAP files were discarded; only the 79 computed features remain

### APEX-IDS2026
- Collected from a **real internet-exposed honeypot** running production-like services (SSH, HTTP, FTP, SIP, etc.)
- Attackers were **real global threat actors** — bots, botnets, human attackers from 40+ countries
- No scripted attacks — all attack behavior is organic and unpredictable
- Raw **NetFlow v9** records captured every 5 minutes via nfcapd/nfdump
- **Zeek IDS** provided deep packet inspection logs (ssh.log, ssl.log, sip.log, etc.)
- Labeling performed via honeypot verification: any IP that triggered a honeypot alert = confirmed attacker
- Cross-temporal global IP verification performed across all 44 days

## 4. Label Quality and Verification

### CIC-IDS2017
- Labels were assigned by the **traffic generator script** — if the script was running an SSH brute force attack at time T, all traffic at time T from that source was labeled "SSH-Patator"
- **Known contamination: ~20%** — documented by Tavallaee et al. (2009) and confirmed in subsequent studies. Normal traffic from the lab's internal network was sometimes captured during attack windows and incorrectly labeled as attack traffic, and vice versa
- **No cross-validation** of labels against external threat intelligence
- Labels are **attack-type specific**: DoS Hulk, PortScan, DDoS, FTP-Patator, SSH-Patator, etc.

### APEX-IDS2026
- Labels assigned via **honeypot verification** — the most reliable method in cybersecurity research
- Any IP that triggered the honeypot's deception layer is definitionally an attacker (zero false positive)
- **Cross-temporal global IP verification**: all 13,638 confirmed attacker IPs were cross-referenced across all 44 days. Any normal flow from a known attacker IP was promoted to the `Attack_Associated` tier
- **Post-purification contamination: 0.00%** — verified by DuckDB scan of all 57.5M normal-baseline flows
- Labels use a **5-tier confidence system** rather than attack-type labels:
  - Tier 1: `Attack_Verified` (honeypot-confirmed, 0% FPR)
  - Tier 2: `Attack_Associated` (known attacker IP in normal window)
  - Tier 3: `Unverified` (ambiguous, not confirmed either way)
  - Tier 4: `Benign_Assumed` (no attacker indicators)
  - Tier 5: `Benign_Verified` (clean IP, clean behavior)

## 5. Data Quality Assessment

### CIC-IDS2017 — Known Issues
| Issue | Details | Impact on ML |
|---|---|---|
| **Infinity values** | 1,509 rows with `Infinity` in `Flow Bytes/s`; 2,867 in `Flow Packets/s` | Models crash or produce NaN outputs without preprocessing |
| **Label contamination** | ~20% of samples may have incorrect labels (Tavallaee 2009) | Trains models on wrong patterns |
| **No raw IPs/timestamps** | Deliberately stripped from published dataset | Cannot do IP reputation analysis, temporal analysis, or reproduce labeling |
| **Single-week bias** | All data from Mon–Fri of one specific week in 2017 | Models may overfit to weekly traffic patterns |
| **Simulated attacker behavior** | Attacks run at specific times in specific ways | Real-world attackers behave differently; models may not generalize |
| **Feature duplication** | `Fwd Header Length` appears twice (columns 35 and 56) | Causes issues in some ML libraries |
| **Stale data (2017)** | Modern attack tools and TTPs have evolved significantly since 2017 | Models trained on this may miss modern attack patterns |

### APEX-IDS2026 — Known Issues
| Issue | Details | Impact on ML |
|---|---|---|
| **Partial Zeek coverage** | Middle capture period has zero Zeek DPI columns | Cannot use Zeek features for all rows; `zeek_available` flag added |
| **No pre-computed features** | Researchers must compute IAT, flow stats from raw data | Higher barrier to entry; needs feature extraction tooling |
| **No explicit attack-type labels** | Tier system does not identify DoS vs Brute Force vs Scan | Cannot use directly in attack-type classification without additional labeling |
| **~241K row gap** | Parquet conversion lost ~241K rows vs original CSVs | Minor; documented; raw CSVs retained as backup |
| **Temporal gap** | One gap period in the 44 days | Breaks strict temporal continuity for time-series models |

## 6. Class Balance

A well-balanced dataset produces more reliable ML model training and evaluation metrics.

| Dataset | Benign | Attack | Ratio | Verdict |
|---|---|---|---|---|
| **CIC-IDS2017** | 80.3% | 19.7% | 4.1:1 | Imbalanced ⚠️ |
| **APEX-IDS2026** | 41.1% | 29.8% | 1.38:1 | Well-balanced ✅ |

CIC-IDS2017's 4.1:1 imbalance means a classifier that labels everything as BENIGN achieves 80% accuracy with no actual intrusion detection capability. APEX-IDS2026's 1.38:1 ratio makes this naive strategy much less effective, forcing models to actually learn attack patterns.

## 7. Feature Comparison

### CIC-IDS2017 Features (79 total — pre-computed)
All features are **derived statistics** computed from the raw PCAP. No raw packet data is available.
- Flow-level statistics: `Flow Duration`, `Flow Bytes/s`, `Flow Packets/s`
- Packet length statistics: Mean, Std, Min, Max (forward and backward separately)
- Inter-Arrival Time (IAT): Mean, Std, Min, Max for flow, forward, and backward
- TCP flag counts: SYN, FIN, RST, PSH, ACK, URG, CWE, ECE
- Bulk transfer statistics: Avg Bytes/Bulk, Avg Packets/Bulk, Avg Bulk Rate
- Sub-flow statistics, active/idle time statistics
- Window size features: `Init_Win_bytes_forward`, `Init_Win_bytes_backward`

### APEX-IDS2026 Features (raw + Zeek)
**Raw NetFlow features (always present):**
- `src_ip`, `dst_ip`, `src_port`, `dst_port`, `protocol`
- `bytes`, `packets`, `duration`, `bps`, `pps`, `bpp`
- TCP flags (raw flags field)
- `first_seen`, `last_seen` timestamps
- Flow direction, interface

**Zeek DPI features (where `zeek_available = True`):**
- SSH: `ssh_auth_success`, `ssh_auth_attempts`, `ssh_direction`, `ssh_client`, `ssh_server`
- TLS/SSL: `ssl_version`, `ssl_cipher`, `ssl_established`, `ssl_subject`, `ssl_issuer`
- SIP: `sip_method`, `sip_response_code`, `sip_user_agent`
- HTTP: `http_method`, `http_status_code`, `http_uri`, `http_user_agent`

**Metadata features:**
- `label`, `confidence`, `tier`, `zeek_available`
- `date` partition key

## 11. Academic Positioning

### CIC-IDS2017's Current Status in Literature
CIC-IDS2017 has been cited **thousands of times** and remains a de-facto benchmark despite known flaws. It is widely used because:
- It was the first large-scale public IDS dataset with diverse attack types
- The pre-computed features make it easy to use
- Historical momentum — existing papers use it, so new papers benchmark against it

However, since 2020, a growing body of literature has **criticized** CIC-IDS2017:
- Tavallaee et al. documented the contamination
- Multiple papers showed models trained on it do not generalize to real traffic
- The 2017 vintage means modern attacks (Log4Shell, Ransomware C2, etc.) are absent

### APEX-IDS2026's Positioning
APEX-IDS2026 does not need to replace CIC-IDS2017. It occupies a **different and more valuable niche**: real-world honeypot captures with verified ground truth. Its natural comparison points are:
- **UNSW-NB15**: Similar real-capture approach but smaller (2.5M flows, 2015 data, lab environment)
- **KYOTO 2006+**: Honeypot-based but very old (2006–2015), no Zeek, no tier system
- **CAIDA datasets**: Real traffic but no attack labels

**APEX-IDS2026 is the largest, most recent, and most methodologically rigorous real-world honeypot IDS dataset available.**

## 13. Gap to Close Before Publication

The two areas where CIC-IDS2017 has an advantage are both addressable:

### Gap 1: Pre-computed ML Features
Compute CIC-style features from raw NetFlow data using a Python pipeline:
- Flow Bytes/s, Flow Packets/s
- Packet length statistics (mean, std, variance, min, max)
- IAT statistics (mean, std, min, max — forward and backward)
- TCP flag counts
- Sub-flow and bulk transfer statistics

**Estimated effort: 1–2 days of scripting.**

### Gap 2: Attack-Type Labels
Enrich existing tier labels with attack-type annotations using port/protocol heuristics:
- Port 22 + high connection rate = SSH Brute Force
- ICMP flood = Ping Sweep/DoS
- Sequential port connections = Port Scan
- SIP method = VoIP attack

This does not need to be perfect — even 70% coverage with a `attack_type` column where deterministic would give ML researchers a useful starting point.

**Estimated effort: 2–3 days of analysis + scripting.**
